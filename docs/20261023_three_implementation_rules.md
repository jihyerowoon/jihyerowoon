# PQ4R 연구설계 2026-10-23: ① 생성 발문 검증 ② 교사 두 경로 ③ PPT-웹입력 연결

> 연구용 PR #1. 운영 사이트(main)는 건드리지 않는다. 현재 실험의 지원 유형은 메타인지적 발문 1유형, 지원 강도 단일 1수준. **지원 문구 동일성까지 강제하지 않는다.** 집단 차이를 지원 주체와 운영 환경의 차이로 기술하고 지원 내용 차이는 로그 분석해야 한다.

## ① 생성형 AI 발문 품질 및 단일 강도
- lib/ai.js: 학생 답변과 은행 기준 예시를 바탕으로 쉬운 질문 한 문장 생성 -> 별도 LLM 품질심사 -> lib/support_policy.js 서버 규칙 검사 -> 전송. 정답/공식/수치/바로 다음 풀이 단계 제시 금지, 초등 5~6학년에게 이해 가능한 표현, 질문 한 개.
- 환경변수 `PQ4R_ENABLE_GENERATION=true`로 **명시적으로 켜기 전 기본 비활성화**. 모델 API 키가 없으면 비활성.
- lib/student.js: 실패 시 승인된 은행 발문을 전송하고 `SUPPORT_SENT.extra`에 `generated`, `generation_mode`, `generation_model`, `source_bank_id`, `validator`, `review_required` 또는 `generation_failed_reason` 기록.
- 위험: LLM 검증도 완벽하지 않음. **생성된 발문 전체를 보존하고, 연구자가 내용 검수하는 절차가 있어야 함.** 실제 독립적인 문항별 내용타당도 평정은 별도.
- **현행 fallback 은행 396개는 구형 어려운 표현을 포함함. 이전에 만든 288개 쉬운 발문 초안을 전문가와 검수 후 현행 fallback 은행을 대체해야 한다.** 288개 초안이 자동 설치된 것은 아님.
- 최소 시험: 학생 오답, 맞았으나 이유 없음, 무응답, 몰라요, 오개념, 맞춤법 오류, 정답을 요구하는 입력, 프롬프트 탈출 유도, 숫자/수식 누출, API 실패, 30명 동시 요청. 출력 1~2문장과 한 수준 유지 확인.

## ② 교사 1명 대 30명: 은행 선택 / 직접 작성
- public/app.js: 라디오로 **준비된 질문 선택** 혹은 **교사가 직접 질문 쓰기**.
- lib/staff.js: 학생 최초 제출 + 도움 요청 + 이전 발문 후 재응답을 확인한 다음 `SUPPORT_SENT` 이벤트와 messages 저장.
- 직접 작성은 lib/support_policy.js 규칙 검증 (질문형, 7~130자, 정답 숫자, 합동 조건, 노골적 풀이 지시 차단). 이를 통과해도 내용타당도 승인 아님. 모든 직접 작성은 **연구자 사후검수 대상**.
- `bank_id`: 정적 발문은 은행 ID, 직접 작성은 `TEACHER_FREEFORM`. `extra.teacher_question_mode`는 `BANK` 또는 `FREEFORM`. `support_text`, `requested_at`, `support_sent_at`, `teacher_id` 기록.
- 기본 전달은 해당 학생에게 **TEXT**. 개별적으로 말로도 실제 전달했을 때만 별도 체크. `delivery_mode=TEXT_AND_PRIVATE_ORAL`의 구두 전달은 **교사 자기보고일 뿐 독립 음성검증 자료가 아니다**.
- 교사가 전체 학생에게 개별 질문을 방송하지 않도록 운영. 자유 발문도 교사가 정답/힌트 내용에 대한 책임을 져야 함. 지원 수, 대기시간, 직접 작성 비중, 채널 차이를 처치충실도에 보고할 것.
- 스캐폴딩 단일 강도란 한 번만 질문한다는 의미가 아니다. 학생 재답 후 재요청 시 동등 강도의 다른 질문 가능.

## ③ 원본 PPT 이미지와 인터랙티브 답변 연결
- 학생용 PPT PNG 34장 압축파일 `활동지_원본PPT이미지_답변입력_독립시연.zip` 준비.
- 개발자는 GitHub 저장소 루트에서 `python scripts/install_worksheet_images.py '<학생용 PNG ZIP 경로>'`를 실행한다. 이 명령이 `public/worksheets/L1_AI`, `L1_TEACHER`, `L2_AI`, `L2_TEACHER` 34장과 `manifest.json`을 생성.
- 파일 설치 후 연구용 브랜치에 커밋하고 Vercel Preview를 다시 확인한다. **정답지 PNG를 public/에 업로드하면 해설 공개시간 6분을 우회하므로 절대 금지**.
- public/app.js가 manifest를 찾아 단계별 원본 PPT 이미지를 보여주고 기존 `ITEM.id` 기반 텍스트/선택형 입력, 제출, 수정, 도움 요청은 그대로 서버 DB로 보낸다.
- 1차시 슬라이드 1 Preview/Question, 2·3 Read, 4·5·6 Reflect, 7 Recite, 8 Review. 2차시 1 Preview/Question, 2~4 Read, 5~7 Reflect, 8 Recite, 9 Review.
- 그룹별 슬라이드 이미지가 동일한 문제를 표시하는지 전수 검사. PPT 자체의 텍스트 박스는 편집 안 되며 **웹 답변칸을 사용**한다.
- Review는 원래 12분: 처음 6분 독립 풀이와 확신도, 6~10분 보호 API 정답 대조, 10~12분 이해도 선택과 짧은 성찰. 기존 모든 실험 데이터 로그 불변.
- 요구 검증: 학생 1명 Preview→Review 전부, AI/교사 그룹 각 1명, 로그인 재시도, 새로고침, 도형 선택, 6분 정답 API 조기호출 거부, 성찰 10분 전 차단, 30명 접속 시 이미지 로딩과 입력 서버 저장.
- Preview DB가 실제 연구 데이터 DB와 같은지 운영 점검 선행. 이미 저장된 로그를 삭제하거나 덮어쓰지 않는다.

## 교수설계 타당성 확인
- AI 발문 생성과 교사 직접 작성이 동시에 가능하면 **지원 문장 통일**을 주장할 수 없다. 대신 지원 목적·유형·강도·개입조건을 공통 운영 원칙으로 삼고 개별 질문의 로그를 자료로 사용한다.
- 검증 기준 최소 5개: (1) 질문형과 자기사고 요구 (2) 정답/수치/공식/풀이 단계 비노출 (3) 학생이 답을 설명하는 데 책임 보존 (4) 쉬운 표현 (5) 같은 수준 정보량. 3~5명의 전문가 평정표는 실제 평가 결과를 기록한 뒤 I-CVI 산출. 수치를 가정으로 기입하지 않는다.
- 참고: Puech et al. 2025, Findings of ACL DOI 10.18653/v1/2025.findings-acl.1348. Qian et al. 2026, Computers & Education DOI 10.1016/j.compedu.2025.105448. AI 질문 생성의 오류 검증이 필요한 선행근거이며 이번 세팅의 타당도를 자체 입증하진 않는다.

# PQ4R 튜터 — 연구용 MVP (mvp-0.5.8 · 단일 메타인지 지원 수준)

> UI 0.5.8: 학생 활동지 문항 선택 상태, 30명 최근 작성 문항 및 자동저장 답안 요약, 교사 도움 요청 알림, 학생과 교사 시간 안내 3분 2분 1분 30초 10초, 학생 질문 원문 기록, 통제집단 구두 발화 수동 전사 기록. 학습 처리 규칙과 기존 append-only 기록은 변경하지 않았으며, 실시간 화면 영상 전송은 지원하지 않는다.



중학교 2학년 PQ4R 6단계 연구용 웹앱입니다. **1차시 「삼각형의 합동」, 2차시 「평행사변형의 성질」 모두 60분**입니다. 두 집단은 동일한 Reflect 검토 설명과 응답란을 사용합니다. 학생이 먼저 답변한 뒤 도움을 요청하면 메타인지적 질문을 **단일 수준 1**로 제공합니다. 학생은 답변을 다시 작성하고 재요청하여 동일 수준의 도움을 여러 번 받을 수 있습니다. 0은 지원을 받지 않은 상태를 뜻하며 별도의 스캐폴딩 수준이 아닙니다. 2026-10-22 새 활동지에 맞춘 연구자 검토용 브랜치이며 운영사이트에는 아직 미배포입니다.

무료 서비스만으로 돌아갑니다: **GitHub(코드) → Vercel(화면·서버 함수) → Neon Postgres(데이터베이스, Vercel 안에서 생성)**. Claude API는 선택이며 쓸 때만 비용이 듭니다. 데이터베이스는 Supabase(서울)로 바꿔 쓸 수도 있습니다(아래 2-B).

```
학생·교사·연구자 브라우저 ──▶ Vercel (public/ 화면, api/ 서버 함수: 판정·발문 선택·기록, 싱가포르 sin1)
                                   │                    └──▶ Claude API (선택, 답 글만 전송)
                                   ▼
                            Neon Postgres (싱가포르. 명단·수업·기록, 기록은 추가만 가능)
```

## 차시와 문항 (mvp-0.4.0)
| 단계 | 1차시 삼각형의 합동 | 2차시 평행사변형의 성질 |
| --- | --- | --- |
| Preview | 두 삼각형 그림 보고 아는 것 쓰기 | 평행사변형 넓이 문제 그림 보고 아는 것 쓰기 |
| Question | 내 질문, 질문이 생긴 이유 | 같음 |
| Read | 개념 정리(합동의 뜻·대응·SSS/SAS/ASA) + 핵심 개념 메모 + 개념확인(합동인 짝 고르기) | 개념 정리(뜻·성질 ①②③·증명) + 핵심 개념 메모 + 개념확인(△ABO≡△CDO에 쓰는 조건) |
| Reflect | 3문제. 실험집단은 **AI의 설명**을 옳다/일부만 옳다/다 틀리다로 판단하고 이유를 씀, 통제집단은 같은 문제를 직접 풀고 이유를 씀 | 3문제. 실험집단은 답 + AI의 설명 판단 + 이유, 통제집단은 답 + 이유(1차시 교사판 방식) |
| Recite | 합동의 뜻, 대응, 합동조건 세 가지 | 뜻, 성질 세 가지 이상, 성질을 기호로 |
| Review | 첫 6분 재풀이와 확신도, 6~10분 정답 대조, 10~12분 짧은 성찰 | 같음 |

- 문항 ID는 차시 번호로 시작합니다(`L1RD02` = 1차시 Read 2번). 기록 CSV의 `lesson` 칸에도 차시가 남습니다.
- 정답 기준·정답·발문 은행(540개 후보)은 활동지를 바탕으로 Claude가 쓴 **초안**이라 연구자 검토가 필요합니다(연구자 → 발문 은행 탭에 "기준 초안" 표시).
- 문제 그림은 활동지에서 잘라 `public/figures/`에, 개념 정리 그림은 `public/materials/S1_…`, `S2_…`에 있습니다. 2차시 Read·Reflect·Recite에서는 평행사변형 조작 도형(꼭짓점·변·각·대각선 선택)도 보입니다.

## 무료로 배포하기 (약 20분)

준비물: GitHub 계정. Vercel은 GitHub 계정으로 가입할 수 있고, Neon 데이터베이스는 Vercel 안에서 만듭니다.

### 1. GitHub에 코드 올리기
현재 코드는 `jihyerowoon/jihyerowoon` 저장소의 `main`에 올라가 있고, 사이트는 https://jihyerowoon.vercel.app 입니다. 새 저장소에 다시 올릴 때만 아래를 따릅니다.
1. github.com → 오른쪽 위 **+** → **New repository** → 이름 입력, **Private** 선택 → **Create repository**.
2. 새 저장소 화면의 **uploading an existing file** → 압축을 푼 폴더 **안의** 파일과 폴더를 모두 끌어다 놓기 → **Commit changes**.
   - `node_modules`는 넣지 않습니다(Vercel이 설치).
   - 명령줄을 쓴다면: `git init && git add . && git commit -m "mvp" && git branch -M main && git remote add origin https://github.com/<아이디>/<저장소>.git && git push -u origin main`

### 2. Vercel 프로젝트 만들기
1. vercel.com → **Add New… → Project** → GitHub 저장소 `jihyerowoon` **Import**. 목록에 없으면 Vercel의 GitHub 앱 권한에 이 저장소를 추가합니다.
2. **Framework Preset: Other** 그대로. 빌드 설정은 건드리지 않습니다(`vercel.json`이 정함).
3. **Environment Variables**에 아래를 넣습니다(`.env.example` 참고). `DATABASE_URL`은 여기서 넣지 않습니다(3에서 자동으로 들어감).

   | 이름 | 값 |
   | --- | --- |
   | `APP_SECRET` | 32자 이상 무작위 문자열 |
   | `TEACHER_PASSWORD` | 교사 화면 비밀번호(8자 이상) |
   | `RESEARCHER_PASSWORD` | 연구자 화면 비밀번호(8자 이상, 교사와 다르게) |
   | `CRON_SECRET` | 무작위 문자열(하루 한 번 점검 작업 보호) |
   | `ANTHROPIC_API_KEY` | (선택) Claude API 키. 없으면 규칙 판정만 |

4. **Deploy** → 1분쯤 뒤 `https://jihyerowoon-xxxx.vercel.app` 같은 주소가 생깁니다(프로젝트 이름에 따라 다름). 아직 데이터베이스가 없어 로그인은 안 됩니다.

### 3. 데이터베이스 연결 (Neon, Vercel 안에서)
1. Vercel 프로젝트 화면 → **Storage** 탭 → **Create Database** → **Neon** → **Continue**.
2. 처음이면 **Create New Neon Account**, 약관 동의 → **Region: Singapore**(서울 지역은 없음, 가장 가까움), 플랜 **Free**, 이름 `pq4r` → **Create**.
3. 이 프로젝트에 연결(**Connect Project**)할 때 Production·Preview·Development를 모두 체크합니다. `DATABASE_URL`이 환경 변수에 자동으로 들어갑니다.
4. **Deployments → 맨 위 배포의 … → Redeploy**. 표는 첫 접속 때 앱이 자동으로 만듭니다(`db/schema.sql`, 붙여 넣기 필요 없음).

### 2-B. (대신) Supabase 서울을 쓰는 경우
1. supabase.com → **New project** → **Region: Northeast Asia (Seoul)**, DB 비밀번호를 적어 둡니다.
2. 위쪽 **Connect** → **Transaction pooler**(포트 6543) URI의 `[YOUR-PASSWORD]`를 바꿔 Vercel 환경 변수 `DATABASE_URL`에 넣습니다.
3. `vercel.json`의 `"regions"`를 `["icn1"]`(서울)로 바꿉니다. 표는 앱이 자동으로 만듭니다(SQL Editor에서 `db/schema.sql`을 직접 실행해도 됨).

환경 변수를 나중에 바꾸면 **Deployments → … → Redeploy**를 한 번 해야 적용됩니다.

### 4. 첫 점검
1. 사이트 → **연구자** 탭 → 비밀번호 → **운영 점검** 탭: 데이터베이스 연결·비밀번호 설정이 "정상"인지 봅니다. AI 키를 넣었다면 **AI 연결 시험**(기대: `CLEAR_INDEPENDENT / CLEAR_INDEPENDENT`).
2. 서버 지역이 `sin1`(싱가포르, Neon과 같은 곳)로 보이는지 확인합니다. Supabase 서울이면 `icn1`.
3. 다음 날 같은 탭에서 "하루 한 번 점검 작업"의 마지막 시각이 찍혔는지 봅니다(Vercel → Settings → Cron Jobs에도 `/api/keepalive`가 보여야 함).
4. 학교 와이파이·태블릿에서 `vercel.app` 주소가 열리는지 미리 확인합니다(일부 학교망은 차단).

## 수업 준비와 진행

**연구자 (수업 전)**
1. **명단** 탭: `학생코드, 집단(실험/통제), 반, PIN(선택)` CSV를 붙여 넣거나 파일로 올립니다. 이름은 넣지 않습니다. PIN을 비우면 4자리를 만들어 줍니다. 오른쪽 **학생** 목록에 PIN이 보이고 **PIN 목록 내려받기**로 언제든 입장 카드용 파일을 받을 수 있습니다(화면을 띄워 둘 때는 **PIN 가리기**).
2. **수업·설정** 탭: 반·차시마다 수업을 만듭니다(예: 수업 코드 `2A-L1`, 반 `2A`, 차시 1차시). **차시** 칸에서 1차시·2차시를 고릅니다. 반을 적으면 그 반 명단 학생만 들어옵니다. 시연·연습용은 **시연용**을 체크해 따로 만듭니다.
3. 설정(AI 판정, 두 번 확인, 문장 다듬기, 짝 문항 관찰, Reflect 개념 정리 열람)을 확인합니다. 바꾸면 기록에 남습니다.

**교사 (수업 중)**: 교사 탭 → 수업 고르기 → **다음 단계 열기**로 진행합니다. 단계를 열면 이전 단계의 미제출 문항이 미완료로 기록되고 학생 화면이 5초 안에 바뀝니다. 왼쪽 대기열에서 통제집단 학생의 도움 요청을 열어 540개 새 메타인지 질문 후보 중 해당 문항에서 추천하는 6개를 우선 검토하고 선택해 학생 화면에 텍스트로 보냅니다. 교사 직접 입력은 비상시 사용하도록 남겼으며, 필수 사유와 원문을 기록하고 전부 연구자 사후 검수 대상으로 표시합니다. 교사 구두 발문은 현재 별도 의무나 인증 기능이 없습니다.

**학생**: 주소 → 수업 코드·학생 코드·PIN → 입장. 새로고침하거나 잠시 끊겨도 이어서 합니다.

**연구자 (수업 후)**: **기록** 탭 → CSV(06 순서) 내려받기와 **전체 백업**을 연구실 저장소에 보관합니다(무료 플랜은 자동 백업 없음). **처치충실도**, **사람 검토**(보류 판정 코딩) 탭을 확인하고, 수업을 **끝내기**합니다.

## Claude API (선택)
- platform.claude.com에서 조직·결제 등록 후 API 키 발급 → Vercel `ANTHROPIC_API_KEY`. 기본 모델 `claude-sonnet-5-5`, effort `medium`(`ANTHROPIC_MODEL`, `ANTHROPIC_EFFORT`로 변경). 파일럿에서 수학교사 코딩과의 일치도로 모델을 정하세요.
- 보내는 것: 문항·그림 설명, 정답 기준, 학생이 쓴 답 글. 학생 코드·PIN·이름은 보내지 않습니다.
- Anthropic 기본 정책: API 입력·출력은 30일 안에 삭제, 허락 없이 학습에 쓰지 않음. 처리 지역은 미국/전 세계 중 선택(한국 없음) → 동의서에 국외 처리 고지가 필요합니다.
- 비용 대략: 실험집단 30명 1차시에서 판정 약 500회(학생당 8회 × 2번 확인 가정) → Sonnet 5.5로 몇 달러 수준. Console의 **Billing → Spend limits**에서 월 한도를 낮게 걸어 두세요.
- 요청 한도에 걸리거나 오류가 나면 그 제출은 규칙 판정으로 처리되고 "검토 필요"로 남습니다(수업은 멈추지 않음).

## 무료 한도와 예상 사용량 (2026-10 기준)
| 서비스 | 무료 한도 | 30명 한 반 60분 수업 |
| --- | --- | --- |
| Vercel Hobby | 서버 함수 호출 월 100만 회, CPU 월 4시간, 비상업·개인 용도 | 호출 약 2만 9천 회, CPU 수 분(로컬 측정 요청당 1~3ms) |
| Neon Free | 프로젝트당 저장 1GB, 컴퓨트 월 100 CU-시간, 5분 쉬면 잠들었다 첫 요청에 깨어남, 되돌리기 6시간·예약 백업 없음 | 기록 수 MB, 컴퓨트 수업당 1 CU-시간 미만 |
| (대신) Supabase Free | DB 500MB, 1주 무활동 시 일시정지, 자동 백업 없음 | 하루 한 번 점검 작업으로 일시정지 방지 |

8차시 × 실험·통제 2반 = 16회 수업이면 한 달에 다 해도 한도 안입니다. Neon은 5분 쉬면 잠들므로 수업 시작 5분 전쯤 교사·연구자 화면을 한 번 열어 깨워 두면 첫 학생 입장이 빠릅니다. 무료 플랜 변경 여부는 운영 전에 각 서비스 가격 페이지에서 다시 확인하세요.

## 보안·개인정보
- 학생 정보는 가명 코드·집단·반만. PIN은 로그인 확인용 해시와, 연구자 화면 표시용 암호문(AES-GCM, 키는 `APP_SECRET`에서 유도)으로 저장합니다. 평문은 저장하지 않고, 교사 화면과 백업 파일에는 PIN이 없습니다. `APP_SECRET`을 바꾸면 목록의 PIN은 '—'로 보이고(로그인은 그대로 됨) **PIN 새로**로 다시 만들 수 있습니다.
- 브라우저용 공개 키로는 어떤 표도 읽을 수 없게 행 수준 보안(RLS)을 켰습니다. 앱 서버만 DB 연결 문자열로 접근합니다.
- 연구 기록(events)은 수정·삭제·비우기를 DB 트리거가 거부합니다. 동의 철회로 삭제가 필요하면 연구 책임자가 Neon(또는 Supabase) SQL Editor에서 트리거를 잠시 끄고 처리한 뒤 사실을 기록하세요.

## 2026-10-23 확정 Review 구성 (연구 검토용 브랜치)

**전체 수업 60분 및 PQ4R 각 단계의 원래 시간표는 유지한다.** 1·2차시 모두 2분 Preview, 2분 Question, 16분 Read, 19분 Reflect, 9분 Recite, **12분 Review** 이다.

- Review 0~6분: 학생이 원문항 RV01 하나를 스스로 풀고 근거를 제출한다. 기존 Review의 RV02, RV03 문항은 학생 화면에서 제외하되 기존 기록을 위해 정의는 보존한다.
- Review +6분부터 +10분까지: 학생의 제출 및 임시 답안을 잠그고 두 집단에 동일한 사전 준비 정답과 풀이 5문항(Review 1, Read 1, Reflect 3)을 서버에서 공개한다. 학생은 자신의 답변과 비교한다.
- Review +10분부터 +12분까지: 학생이 문항 하나를 선택하고 이해 정도 3단계 중 하나를 선택하며, 새롭게 이해한 점 또는 아직 어려운 점 **한두 문장만** 성찰로 기록한다. 기존 2개의 긴 서술란을 1개로 축소한다.
- 서버에 `REVIEW_PRE_SNAPSHOT`, `REVIEW_FEEDBACK_OPEN`, `REVIEW_POST_REFLECTION` 이벤트를 학생별로 보존하고 기존 로그 필드 구조를 삭제하거나 변경하지 않는다.
- `GET me/review-feedback`는 해당 수업 Review가 열린 시각 +360초 전에는 403으로 해설을 거부한다. `POST me/review-reflection`는 +600초 전에는 403으로 거부한다.
- **두 집단 같은 공개시각 조건:** 두 집단이 동일 수업 세션을 공유할 때만 동일한 공개 절대시각이 적용된다. 서로 다른 세션이면 별도의 동기화가 필요하다.
- 원본 활동지와 대조할 수 있도록 정답이 포함되지 않은 학생 작성용 PPTX 4개와 공통 정답지 PPTX 1개를 별도 파일로 관리한다. 정답지에는 AI/교사 지원 집단 구분을 두지 않는다.
